================================================================================
1. GAMBARAN UMUM PROYEK (PROJECT OVERVIEW)
================================================================================
Proyek ini adalah aplikasi Enterprise Resource Planning (ERP) dan Sistem Informasi
Manajemen Operasional terpadu yang dirancang khusus untuk mendigitalisasi alur bisnis
pabrik pengolahan kaca dan toko kaca (studi kasus PRD: CV Cahya Karunia Jaya).

Masalah utama yang diselesaikan oleh sistem ini meliputi:
a. Menghilangkan pencatatan manual berbasis kertas SPO (Surat Potong Orderan) yang
   rawan salah tulis (human error), hilang, atau sulit dilacak.
b. Melacak progres produksi kaca secara real-time lintas 4 divisi pengerjaan:
   - Divisi HT (Gosok Kasar Manual Batu / Potong & Bor)
   - Divisi GM (Gosok Mesin / Pinggiran Halus)
   - Divisi BV (Bevel Pinggir Permukaan)
   - Divisi Etsa (Sandblast / Blur Kaca)
c. Mengoptimalkan pemanfaatan Kaca Sisa (Scrap Glass) hasil potongan di rak gudang
   melalui fitur Smart Scrap Recommendation saat kasir/admin toko membuat order baru.
d. Mengelola siklus inventori (Kaca Lembaran Utama, Aksesoris, Bahan Habis Pakai /
   Supplies, Peminjaman & Servis Alat/Mesin Kerja, serta Data Supplier).
e. Mengatur pengiriman armada, pencetakan Surat Jalan 3/4 rangkap warna (Putih,
   Merah, Kuning), Surat Barang Keluar (Gate Pass Satpam), konfirmasi foto bukti
   pengiriman oleh Supir, hingga penyetoran uang tagihan COD.
f. Mengelola pembukuan keuangan (Laporan Laba Rugi / P&L, HPP, OPEX, Klaim Bensin/Tol
   Supir) serta manajemen akun karyawan & log aktivitas (HRD).

2. TECH STACK, FRAMEWORK, & VERSI (BACKEND & FRONTEND)
================================================================================
Aplikasi ini dibangun menggunakan arsitektur Modern Monolith (Single-Page Application
tanpa perlu membuat REST API terpisah menggunakan jembatan protokol Inertia.js):

A. Bahasa Pemrograman:
   - Backend  : PHP ^8.2
   - Frontend : JavaScript (ES6+ / JSX React)
   - Styling  : CSS3 (Utility-first via TailwindCSS)
   - Query    : SQL (MySQL / SQLite via Laravel Eloquent ORM)

B. Framework Utama:
   - Backend Framework  : Laravel Framework ^12.0 (struktur kompatibel Laravel 11/12)
   - Frontend Library   : React ^18.2.0 + React DOM ^18.2.0
   - Fullstack Adapter  : Inertia.js (`inertiajs/inertia-laravel` ^2.0 & `@inertiajs/react` ^2.0.0)
   - CSS Framework      : TailwindCSS ^3.2.1
   - Module Bundler     : Vite ^7.0.7

4. ARSITEKTUR DATABASE, JUMLAH TABEL, & STRUKTUR SKEMA LENGKAP
================================================================================
A. Mesin Database (DBMS):
   - Mendukung penuh **MySQL / MariaDB** (`driver: mysql`, port `3306`, charset `utf8mb4`)
     untuk lingkungan produksi/server, serta **SQLite** (`database/database.sqlite`)
     untuk kemudahan pengujian lokal (dikonfigurasi melalui variabel `DB_CONNECTION` di `.env`).
   - Jumlah Database: **1 Database Terpusat** (Single Relational Database).

B. Jumlah Tabel:
   Total terdapat **22 Tabel** di dalam database (dibentuk dari 24 file migrasi), yang
   terbagi menjadi:
   - **13 Tabel Bisnis & Operasional Utama**
   - **9 Tabel Infrastruktur, Autentikasi & Sistem Bawaan Laravel**

       - `created_at`, `updated_at` (TIMESTAMP)

   *(Catatan: Bersama `users`, total tabel domain aplikasi adalah 14 tabel).*

7. ALUR BISNIS & FITUR UTAMA END-TO-END
================================================================================
1. PENERIMAAN ORDER & DETEKSI KACA SISA:
   Customer memesan kaca -> `admin_toko` menginput ukuran, ketebalan, opsi proses (HT, GM, BV, Etsa),
   dan aksesoris di `NewOrderModal` -> Sistem otomatis mengecek apakah ada Kaca Sisa (`ScrapGlass`)
   di rak yang cocok -> Jika masih belum deal disimpan sebagai `draft`, jika sudah deal/DP masuk ke
   status `pengerjaan`.

2. DISTRIBUSI & EKSEKUSI 4 DIVISI PRODUKSI:
   Order berstatus `pengerjaan` muncul di dashboard `admin_gudang` -> Admin Gudang menekan tombol
   Distribusi ke divisi pertama (`divisi_ht`) -> Staf Divisi HT menekan "Mulai Kerjakan", memotong kaca,
   mencatat jumlah lembar kaca bahan yang terpakai serta menginput ukuran potongan sisa kaca baru ke
   rak melalui `DivisionExecutionModal` -> Setelah HT selesai, order otomatis mengalir ke divisi
   berikutnya sesuai opsi pesanan (`divisi_gm` -> `divisi_bv` -> `divisi_etsa`).

3. PENANGANAN REVISI & KOMPLAIN KACA CACAT:
   - Jika customer meminta perubahan ukuran/spesifikasi saat kaca sedang diproduksi, `admin_toko`
     mengirimkan Revisi -> sistem mengunci order sementara dan memberi notifikasi prioritas ke divisi
     tempat kaca tersebut berada saat ini.
   - Jika staf divisi menemukan kaca baret/pecah/gagal produksi, staf menekan tombol Masalah Kaca
     (`ComplaintModal`) dan mengunggah foto bukti -> `admin_gudang` memeriksa di `GudangDecisionModal`
     untuk menyetujui potong ulang (Re-cut kembali ke Divisi HT) dan memindahkan kaca cacat ke stok sisa.

4. PENGIRIMAN, SURAT JALAN 4 WARNA, GATE PASS, & PELUNASAN COD:
   Setelah seluruh divisi selesai (`ready_ship`), `admin_toko` / `admin_gudang` menjadwalkan pengiriman,
   memilih supir & kendaraan, serta mencetak Surat Jalan (`WaybillModal` / `BatchWaybillModal`) dengan
   ketentuan warna:
   - Lembar PUTIH  : Untuk konsumen jika sudah Lunas (atau dibawa penagih/DC jika belum lunas).
   - Lembar KUNING : Untuk arsip Admin Gudang.
   - Lembar MERAH  : Diserahkan ke konsumen sebagai tanda terima sementara jika belum lunas (COD).
   Petugas `satpam` memverifikasi barang keluar di pos gerbang (`GatePassModal`) -> `driver` mengantar
   barang, memfoto surat jalan yang sudah ditandatangani penerima (`ConfirmDeliveryModal`), dan jika
   ada pembayaran COD di tempat, supir menyetorkannya ke kasir toko (`CodSettlementModal`).
